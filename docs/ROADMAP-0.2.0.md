## Pi 的最终架构

选型阶段对比了完整 Pi CLI 与 DSH 发布包。正式实现选择 **Pi Agent SDK 调度 + 现有受控模型/工具执行层**：

1. Pi 的 Agent 类负责消息、工具调度、steering 和完成状态。每次任务启动独立 Node 进程，不加载 Pi CLI 的插件、Skills、全局配置或凭据库。
2. 每次模型请求通过 JSONL 桥回到 Python，在供应商调用前检查累计预算、轮次、上下文和取消。沿用当前 Chat Completions 兼容链路及思考历史保留逻辑。
3. 工具执行也回到 Python，继续使用现有隔离工具进程、写入清单、任务目录、无进展检测、命令环境和原子写入 journal。
4. Node 进程没有 API Key。工具子进程同样不继承模型 Key；Node 在 Windows Job Object 中受父进程管理。
5. 正常取消等待实际执行退出再释放租约。GUI 生命周期与 Codex 持有的 MCP 执行引擎保持分离。

这样避免另写一套弱化的文件操作层，也不需要将供应商 Key 交给第三方 shell 工具。命令仍是 trusted-host 执行，并非 OS 文件沙箱。

Pi coding 在工具执行前保存工作区基线，结束后保留有净变化或覆盖不完整的检查事项。恢复查询返回观察差异、当前文件哈希及状态摘要；主代理提交对应 review_id、state_sha256 和独立检查依据才能确认。精确 journal 的确认是另一项操作，二者不会互相冒充。

## MCP 兼容

保留原 12 个工具，增加 12 个中性/恢复入口，共 24 个：

- start_agent、start_agent_readonly、delegate_to_agent、delegate_to_agent_readonly。
- get_task_status、get_task_result、send_task_message、cancel_task、record_task_verification。
- get_task_recovery、acknowledge_task_mutations、acknowledge_workspace_review。

旧 DeepSeek 启动/委托工具始终使用原引擎，不会因 UI 选择 Pi 而悄悄换后端。控制工具通过任务 ID 路由；已有任务保持启动时配置。

升级后，在设置中“更新托管规则”并重启 Codex，以加载中性工具与新规则。原有用户规则、主模型和其他 MCP 保留；已有工具允许/禁止清单也保留，若清单限制了新工具，需要用户按自己的权限政策调整。

## 用量与日志的边界

- 任务结束日和请求发生日是两套分别展示的视图。旧任务没有请求事件时明确列出缺口，不猜测请求时间。
- 供应商报告与本地预算计量分开。重试、中断及供应商未返回的账单不可精确补算；所有金额仍是估算。
- 缓存命中未知时采用区间；reasoning 不重复加到已包含它的输出 token。日志中存在额外缓存写入费用时，不套用缺少该费率的简单公式。
- 解析器只保存统计元数据、版本、计数和游标。正文与用量混存的文件会被扫描，但正文不落入本软件缓存、界面、诊断或网络。
- 当前本机日志已用两条用量记录做过字段结构核对，只输出字段名，没有保存正文。构造测试同时覆盖旧累计格式；这不代表支持所有历史/未来 Codex 版本。
- 混合单次/累计链路优先单次，跳过可能重复的累计链并提示覆盖缺口；无法确认归属的累计分支基线不伪造消费。
- 每轮扫描限制时间和字节数；超大正文行分段跳过并报告，完整行游标持续推进，正在追加的半行留给下一次读取。扫描有实际进展时界面继续补齐，普通刷新独立于两秒状态轮询。
- 删除/清理源日志前已导入的统计可以留在派生缓存中；停止后可明确清除该缓存，原日志不删除。卸载选择清理历史时，也清除新统计数据和日志启用设置。

## 使用本地构建

安装本地 0.2.0 后，先保持原供应商与开关状态；需要 Pi 时在“设置与诊断 → 执行后端”选择组合。真实后端测试按钮会消耗供应商额度。更新托管规则、重启 Codex，再在新聊天中核对 ping 的 workspace 和 active_backend。

日志对照默认关闭。用量明细中的费用与价格差为估算，配置模型单价后才展示；缺价或缺用量不伪装为零。
