# 发布后实现复核

本轮从已发布的 0.4.0 源码增量检查正常操作，修复实际复现的流程缺口。本文件保留提交前的本地验证快照；这些改动与后续对抗审查修复一起纳入 [0.4.1](RELEASE-0.4.1.md)。GitHub 的旧 0.4.0 安装包不包含本轮修复。本轮没有付费模型请求，也没有修改日常 Codex 配置、安装或委托开关。

## 已修复行为

| 范围 | 原问题 | 当前行为 |
| --- | --- | --- |
| 供应商保存 | 原样保存或改显示名也更换修订，验证证据与价格失效 | 无执行配置变化、同一凭据保留修订及证据；实际模型、协议、执行配置或 Key 变化仍使旧证据失效 |
| 分层连接验证 | Pi 未安装也禁止模型 quick/full | 模型响应和工具协议验证独立可用；实际后端验证仍需可用后端 |
| 连接错误与费用 | 参数、服务端、网络错误一律泛化；缓存写入缺计量无解释 | 区分安全错误分类与 HTTP 状态；展示缺口，显式零费率可以确定费用但不补造计数 |
| 自有接入更新 | 跨运行时修复后误判为外来注册 | 预览具体命令变化，应用后按实际命令保留归属；仅更新规则不擅改入口 |
| 基础接入 | 新注册选择基础能力仍暴露全部工具 | 新注册落盘 7 个基础只读／身份工具；保留已有额外配置与显式拒绝 |
| 聊天验证界面 | 查询未传聊天身份，“当前聊天已验证”不可达 | 明确选择报告后带实例、工作区、会话和报告 ID 查询；轮询不丢选择，重开 App 要重新选择 |
| 验收与续作 | `passed=false` 与 `verified_complete/partial` 可矛盾共存 | 拒绝失败核验授予完成／部分通过；历史失败记录不能用于续作 |
| 评测界面 | 档位固定 Flash，价格与失败结局只能用 CLI | 可冻结 Pro、推理设置、环境、订阅／API 计费、参考价与来源；登记失败、未派工原因和接手；金额上限显示冻结币种 |
| 评测错误 | 开始／结束失败后仍刷新，掩盖错误 | 只在成功后刷新实验，失败信息保留且不自动重放 |
| 追加日志计量 | 重读同一事件永久降覆盖，正常累计计数缺响应 ID 也被拒绝完整计量 | 重读幂等；明确绑定的单调累计链可计量；逐请求／累计来源按会话协调，无法证明重叠时展示下界和缺口 |
| 未派工记录 | 已登记 Run 但请求在发送前被拦截，无法记录真实未派工 | 没有请求获准发送时可记录未派工及原因，保留已知主模型成本；已有请求记录仍需核对发送证据 |
| 后建子聊天 | 初次绑定之后无法追加新的相关会话 | 明确确认后追加相关 session，保持 root／主 session 不变并核对跨试次归属 |
| 长日志与写入中日志 | 超过 16 MiB 整体拒绝，末尾半行或正常追加永久降覆盖 | 有界流式读取；半条尾行待补完，固定已读前缀允许追加，真实覆盖／截断仍保留缺口 |

预算、配置并发检查、显式拒绝、恢复核验和证据版本检查是既有合同，本轮保留。没有为容忍无效状态新增自动重试、回退执行或自动改开关。

## 验证与证据

本轮证据独立保存于 `artifacts/evidence/implementation-review/`，不覆盖发布包证据。

- `connection-functional-audit.json`：5 个针对性测试、前端构建、浏览器加真实 Python RPC 的结果摘要；原始 console 未持久化，文件明确注明。
- `integration-usability-unit.log`：21 项接入测试通过。
- `integration-ui.json`、`integration-usability-ui.log`：生产前端加真实 Python RPC；跨运行时修复、基础名单、显式聊天选择、轮询和重开失效。聊天调用元数据为隔离 fixture，不是真实 Desktop 验收。
- `evaluation-ui.json`：生产前端加真实 Python RPC；Pro 模型、带来源参考价、计费方式、15 个隔离材料、授权预览、失败信息、未派工／失败／接手登记和报告。请求数为 0；测试只在隔离数据库授权零外部 Token。
- `unit-regression.log`：全量 298 项通过，201.650 秒。该次覆盖首批全部修复；后续子聊天／长日志改动另执行受影响评测回归，结果单列。
- `evaluation-final.log`：最终受影响评测 50 项通过，4.789 秒；包括关联会话、17 MiB 正常日志、尾行补完、并行追加／前缀改写及模型切换计量。与全量测试存在重叠，不把两个数字相加。
- `execution-mcp.json`、`execution-mcp.log`：双实际后端通过真实 stdio、文件工具、恢复门禁和仅剩余事项续作；失败核验不能授予完成。模型响应来自本地替身。
- `native-roadmap.json`、`native-roadmap.log`：实际 Tauri／WebView2 与 bundled Python／Pi，通过原生 RPC、Windows 授权窗口、冻结预算、日志与价格流程；18 次请求全部发往隔离本地 HTTP 服务。
- `local-build.log`：TypeScript、Vite 与 Rust release 构建通过。本轮没有重新制作或发布 NSIS 安装包，也没有重复旧安装升级验证。
- `delivery-verification.json`：本地 exe 哈希、变更源码哈希、27 个 engine 文件与两个运行时副本逐一一致；使用构建目录的 Python 实际调用新增 related-session RPC，确认入口与明确确认门禁可用。

先前版本保存的缺少来源元数据、重复冲突或未归属问题不会被自动抹去；本轮改进保证新导入的正确行为。需要重新建立完整计量依据时，新建独立试次并显式绑定，不重置旧消耗。

27 项 PRD 验收的发布基线保留在 [DELEGATION-ACCEPTANCE.md](DELEGATION-ACCEPTANCE.md)。本轮加强 I-A02／04／05／08、C-A01／04／05／06、L-A02／03／05、E-A02／03／04／05 的正常流程覆盖；不会因此提升真实客户端／付费实验的验收状态。L-A01 六个真实聊天、真实模型质量／账单／净收益仍未验证，日常升级也未执行。
