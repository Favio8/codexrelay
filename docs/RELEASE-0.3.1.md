# 0.3.1 Windows Beta：预算、上下文与核验后续作

本次公开版本包含 0.3.0 本地迭代的 M1—M4 和 0.3.1 低预算修复。[GitHub Release](https://github.com/Favio8/codexrelay/releases/tag/v0.3.1) 提供 Windows x64 安装器、完整源码、验收证据、许可文件和 SHA256。仍按未签名 Windows Beta 发布。原始 PRD 和此前本地交付包保留。

## 相对 0.2.2 的完整功能

- 原引擎与 Pi 共用预算和供应商调用层；显示预算来源，有界读取和重复读取反馈。
- 结构化进度摘要、合法 ContextEpoch 重建、Pi 调度状态同步；摘要、重试和执行都纳入当前 Run 消耗。
- 持久化 TaskGroup、独立 Run、checkpoint、实际工具证据、旧上下文归档和恢复引用。
- 每轮由 Codex 核验真实成果，只委派剩余事项；幂等续作默认允许 3 次，初始执行加至多 4 轮。
- App 可调整新任务默认次数，为当前任务追加次数或调整后续预算；历史消耗与次数不会因压缩、重启或后端切换清零。
- implementation/testing/review/analysis/documentation 合同明确；总开关、项目禁用、取消、恢复事项及次数限制对续作生效。
- 保留 0.2.2 的管理窗口单实例和 NSIS 原目录升级修复。

从 0.2.2 升级时 SQLite schema 1 原子迁移到 4，保留供应商、预算、开关、历史和恢复记录；旧任务不伪造组或核验。0.3.0 到 0.3.1 没有额外数据迁移。Pi Agent Core 仍为 1.2.0。

升级前结束活动委托。安装器退出空闲旧管理窗口和执行引擎，沿用原目录。升级后在「设置与诊断」更新托管规则并重启 Codex，以加载新增 MCP 工具。用户主模型、登录和其他规则继续保留。

## 修复与原因

此前单行 JSON 样本在 32,768 Token 预算下：原引擎修改正确但执行停止，Pi 没有完成修改。通用的“修改前必须 Read”让模型即使有匹配片段仍倾向读取长行；分页工具输出又在后续请求中反复计费，过晚的预算反馈来不及为修改和最终报告留空间。

执行合同现在明确 Read 或 Grep 都可提供编辑依据；已知路径直接搜索，命中的真实片段即可用于精确 Edit。长行默认 2,000 字符预览并提示搜索目标，显式范围和完整读取仍受原有边界支持。首个请求告知本轮累计预算；余量不足约三次当前输入及短输出时提前提示收敛。修改后只验证相关范围，整份 JSON 检查可用解析器返回短结果。硬预算、工具授权和父代理验收规则保持原有语义。

思考模式摘要的既有修复保留：在官方 DeepSeek 接口使用同一模型的普通模式生成结构化摘要，执行保持 high。两后端的真实摘要和重建后请求此前均已成功，本次完整回归继续覆盖合法工具交换、原 reasoning_content 保留、Pi 调度状态同步及失败降级。没有把 Pi Agent Core 当作完整编程代理。

## 真实模型结果

使用原来的 30,629 字节单行 JSON、900 个 items、同一现有模型 deepseek-flash、high 推理、每轮 32,768 累计预算及 2,048 输出上限。任务文本和判据不变，不使用续作。

| 后端 | 旧补测本地计量 / 结果 | 0.3.1 本地计量 / 结果 | 产生首次修改的请求序号 |
| --- | --- | --- | --- |
| 原引擎 | 30,339 / 修改正确，执行停止 | 16,000 / 执行完成，父代理验收通过 | 3 |
| Pi | 29,322 / 修改未完成 | 13,695 / 执行完成，父代理验收通过 | 2 |

新样本分别报告 15,969 和 13,695 Token，本地计量与供应商报告分列保存。Codex 检查实际文件与原始字节，只允许 false → true；900 个 items、其他内容和格式均未改变。两个精确 Edit 事务和一个 Pi 观察检查在核对当前哈希后确认，命令均成功，两个最终报告均存在。

这是每后端一个真实样本，证明所标出的具体失败场景已解决，不推导任意任务的固定节省率。全部已授权实测现为 29 次，本地累计 418,636 / 655,360 Token；缺少模型价格配置，金额未知。此前截断和失败样本仍保留，没有从统计中删掉。
